# @vcmap/print

> Part of the [VC Map Project](https://github.com/virtualcitySYSTEMS/map-ui)

## General

The Print plugin enables the user to create images and PDFs from the current view of the map. The main difference to the OS or browser integrated screenshot tool is that the user has impact on the quality of the created image and only specific elements of the map are printed on the image. Furthermore a PDF file with the image and additional information can be created.

**PDF export with an active, scale-defined print-area rectangle** does not take a screenshot of the current view. Instead, the map image is assembled directly from the active WMS/WMTS/vector layers at exactly the requested bounding box, scale and resolution (`PrintCompositor`). This avoids scale inaccuracies caused by the browser window size or by the map's own rendering projection (see `printEPSG` below), and lets the user print an extent independent of what currently happens to be visible on screen. Without an active print-area rectangle — and for the plain image/JPEG mode — the classic screenshot-based approach (a capture of the current view) is still used.

In the image/JPEG mode, the user can select a resolution. Each time the window size is changed the resolution adapts accordingly. When pressing the "CREATE"-Button a screenshot of the map is created and downloaded.

In the PDF mode the user can select the page format, the pixels per inch (ppi) and, if configured that way, can add a title and a description. Furthermore it is possible to configure the PDF mode in a way that contact credentials and map information (like coordinates of the current view) are added below the image, each time a PDF is created. When at least one layer with a legend is active and if the plugin configuration enables that, the user can choose to print the legend. If a FeatureInfo window is active and if the plugin configuration enables that, the user can choose to print this window on the PDF. When printing via an active print-area rectangle with `printEPSG` configured, the coordinates of the top-right and bottom-left corner of the printed extent are additionally printed next to the map (X above/below the map, Y rotated next to the map), labelled with the projection's name.

> **Note**: Chromium based browsers cannot properly create a screenshot of Cesium maps, if the target resolution exceeds a total pixel count of thirty-three million. To avoid this either reduce the resolution or use Mozilla Firefox browser, which can handle larger pixel counts. This limitation applies to the screenshot-based paths (image/JPEG mode, and PDF export without an active print-area rectangle) — PDF export via an active print-area rectangle uses direct layer compositing instead and is not affected by this limit, but is currently only available for the 2D map.

> **Note**: Because WMS layers are fetched directly by the browser for the print-area-rectangle PDF path, the configured WMS services must send appropriate CORS headers (`Access-Control-Allow-Origin`) on their GetMap responses. A layer whose WMS server does not send these headers will silently be skipped (logged to the browser console) rather than aborting the whole print.

## Configuration

To add and configure the plugin add an entry with name @vcmap/print to the map's config plugins section. Below the possible configuration options and their defaults are listed.

### image/JPEG

| key               | type            | default                    | description                                                                                                                                                                                                                                                                                 |
| ----------------- | --------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| resolutionList    | Array\<number\> | `[500,720,1280,1920,3840]` | List of possible resolutions. Each resolution consists of only one value. This is always the longest side of the image. Thus, if the width of the map is bigger than the height, the width is the selected value of the resolution list and the height is calculated from the aspect ratio. |
| resolutionDefault | number          | `1280`                     | The default resolution. Needs to be a value of the resolutionList.                                                                                                                                                                                                                          |

The first matching rule (in list order) wins per layer. |

> **Note**: The page format specific styling of the PDF can not be modified by the map config file or by the user. If changes are necessary these have to be applied in [source code](#format-specific-styling) (./src/pdf/styles.ts).

## Development notes

### Unlock new PDF page formats

For unlocking new page formats the following steps are required:

1. Extend the allowed format types in the jsdoc at the constructor of PDFCreator and the PrintConfig typedef in src/common/configManager.ts.
2. Remove comment characters in src/pdf/standardPageSizes.ts if necessary
3. (optional) add [format specific styling](#format-specific-styling) to 'src/pdf/styles.ts'.
4. Add the new format to README documentation.

### Format specific styling

In order to change the styling of a specific page size/format, a new key has to be added to the 'pageStyle' object in `./src/pdf/styles.ts`. The key must be the name of the format (e.g. `A6: {}`). Only the relevant keys need to be changed. These will override the keys of the default styling for this specific format.

### Layer handling for print-area-rectangle PDF export (`PrintCompositor`)

When a PDF is printed via an active, scale-defined print-area rectangle, `src/pdf/printCompositor.ts` builds the map image layer by layer instead of relying on `renderScreenshot`, in this order per active layer (`buildPrintLayers` in `src/pdf/pdfWindow.vue`):

1. **`pattern` match** — if the layer's URL matches a configured rule, it is printed as a WMS layer using the rewritten URL (see the `pattern` config option above).
2. **WMS layers** (`WMSLayer`) — fetched directly via a GetMap request built from the layer's own `url`/`parameters`/`version`/`getLayers()`.
3. **WMTS and vector layers** (`WMTSLayer`, `VectorLayer`) — rendered via a temporary, off-screen OpenLayers map, since both need actual rendering (tile compositing / feature styling) rather than a single image request. Vector features are explicitly reprojected first if the map's live projection differs from `printEPSG`, since — unlike tile sources — OpenLayers does not reproject vector sources automatically.
4. Any other/unrecognised layer type is skipped.

A currently open limitation: swipe-tool and FeatureInfo overlays (`overlayWindows` in `pdfWindow.vue`) are not yet composited into a `PrintCompositor`-based PDF, since their positioning is derived from the live browser viewport rather than the printed bounding box. They are still printed for the screenshot-based fallback path (no active print-area rectangle).
